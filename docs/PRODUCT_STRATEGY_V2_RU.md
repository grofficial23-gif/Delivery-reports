# PM Delivery Reports — Product Strategy v2

## Куда двигаем продукт
Цель: превратить текущий Telegram-бот + Mini App из личного инструмента в SaaS-сервис для PM-ов с подпиской, постоянным HTTPS и понятной монетизацией.

## Базовый пользовательский поток
1. Пользователь открывает `Mini App` из Telegram.
2. Добавляет один апдейт за раз: `проект -> эпик -> статус -> что сделано -> что дальше -> блокеры -> ссылки`.
3. Видит список `Сегодня уже добавлено`.
4. Собирает digest в одном из стилей:
   - баланс;
   - только главное;
   - для руководителя;
   - для команды.
5. Копирует `Telegram-ready` текст или отправляет его себе в Telegram.
6. При необходимости фиксирует финальный отчет.

## GRACE-фреймворк продукта
Это рабочая схема, под которую стоит держать весь UX.

### G — Gather
Собрать апдейты без боли:
- текст;
- voice;
- Mini App;
- project / epic / Jira / ссылки.

### R — Resolve
Досопоставить контекст:
- определить проект;
- привязать эпик;
- показать `нужно уточнить`, если система не уверена.

### A — Assemble
Собрать digest:
- сжатие длинных пунктов;
- шаблоны по аудитории;
- plain-text версия для Telegram;
- разбиение на несколько сообщений, если отчет длинный.

### C — Communicate
Отправить результат:
- себе в Telegram;
- в рабочий чат;
- в письмо / Confluence / таск;
- позже: weekly / monthly / PDF / Word / презентация.

### E — Expand
Расширять продукт:
- Premium-планы;
- админка;
- командные шаблоны;
- white-label.

## Деплой
### Рекомендуемый вариант: Railway
Почему:
- есть постоянный HTTPS URL;
- есть persistent storage для SQLite;
- Mini App работает без временных tunnel URL;
- деплой через git push.

### Базовый production-flow
1. Подключить GitHub-репозиторий к Railway.
2. Задать переменные окружения.
3. Включить persistent volume под SQLite.
4. Получить постоянный HTTPS URL.
5. Поставить этот URL в `PUBLIC_WEB_APP_URL`.
6. Прописать его в BotFather для menu button Mini App.

## Telegram monetization
Основной вариант:
- Telegram Stars.

Почему:
- нативно внутри Telegram;
- подходит под цифровой продукт;
- пользователь покупает PRO, не покидая экосистему Telegram.

Второй вариант:
- Stripe для web-based админки и B2B-оплаты.

## Premium differentiation
### Что должно оставаться в FREE
- базовый сбор заметок;
- один стандартный стиль;
- один daily digest;
- базовый Mini App.

### Что должно уходить в PRO
- rich-format;
- несколько шаблонов;
- weekly summaries;
- экспорт;
- AI-редактор;
- voice.

### Что должно уходить в TEAM
- monthly;
- презентации;
- документация;
- shared templates;
- admin analytics.

## UX-принципы
- Один апдейт = одна сущность.
- Пользователь всегда видит, что уже добавлено за день.
- `Inbox` никогда не торчит как основной блок: только как `Нужно уточнить`.
- `Follow-up` не смешивается с daily-апдейтами.
- Главный output всегда дублируется в plain text.
- Если текст длинный, система сама режет его на части для Telegram.
