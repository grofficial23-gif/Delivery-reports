# PM Digest Functional Baseline Audit

**Дата актуальности:** 27 апреля 2026 г.  
**Язык:** русский (функциональный базовый аудит).  
**Источник:** агрегированный аудит Telegram-бота и веб-части (read-only анализ кодовой базы).

---

## 1. Executive summary

**Известный продакшн-бот:** [@igest_bot](https://t.me/igest_bot) · `bot_id: 8603110674`  
**Известный super admin:** [@PM_vibe](https://t.me/PM_vibe) · перменная `SUPER_ADMIN_USERNAMES`, значение по умолчанию: `PM_vibe`

Продукт — **PM Digest**: бот с polling, заметки (текст/голос), черновики и финальные отчёты, Mini App (веб-кабинет), подписки FREE/PRO/TEAM, оплата через **Telegram Stars** (XTR), super admin в Telegram и команда/супер-админ в веб-админке.

**Ключевой вывод:** **V2 должен быть новым слоем UX/UI поверх уже работающей логики бота, веба, админки и подписок, а не переписыванием ядра.**

**Важное предупреждение:** не создавать дублирующие маршруты, команды бота, поток оплаты или логику подписок без явного запроса.

## 2. Bot entrypoints

- **Единая точка входа:** `src/delivery_reports/main.py` → функция `run()`.
- Загружаются настройки, БД, репозиторий, сервис транскрипции; бот и веб **в одном процессе** (uvicorn + FastAPI с общим `lifespan`).
- Бот собирается через `build_app()` в `bot_app.py`, далее: удаление webhook и pending updates, `start_polling(drop_pending_updates=True)`.
- Режим: **long polling** (подходящий для развёртываний вроде Render; не webhook).

## 4. Message handling

- **Текст:** сначала кнопки reply-клавиатуры, затем сценарии «ожидания правок черновика», `проект:`, `эпик:`, `менеджер:` / `руководитель:`, исправления «не X, а Y», привязка к проекту, smart-ввод, иначе — сохранение как заметка.
- **Голос:** скачивание `.ogg` → транскрипция → `capture_notes` или fallback при ошибке.

**Замечание к baseline:** в `PLAN_LIMITS` у FREE `voice_notes: False`, но **в обработчике голоса проверка плана не обнаружена** — фактически все могут диктовать.

## 5. Mini App / Web App integration

- URL Mini App: из **`PUBLIC_WEB_APP_URL`**; функция в боте дополняет путь до **`/dashboard`**, если не HTTPS — кнопка не показывается; есть сообщение про необходимость настроить переменную.
- Использование: inline-кнопка Web App, `/app`, `MenuButtonWebApp` в чате.
- В веб-контекст передаётся `public_web_app_url` (детали — в `web_app.py`, не дублируем здесь).

**Документация env:** `PUBLIC_WEB_APP_URL` **нет** в публичном `.env.example` — риск для онбординга, не ломает прод.

## 6. Payments / Telegram Stars

- Валюта: **`XTR`**, `provider_token` пустой (Stars).
- **PRO:** 250 Stars, payload `invoice_pro_1m`.  
- **TEAM:** 700 Stars, payload `invoice_team_1m`.  
- Pre-checkout валидирует payload; успешная оплата пишет подписку +30 дней, для TEAM создаётся команда и **инвайт-ссылка** вида `t.me/igest_bot?start=team_{user_id}` (username бота **зашит** в строке).

**Несоответствие копирайта в `/pro`:** в тексте команды встречается оговорка, что Stars «будет следующим этапом» — **устарела**, оплата в коде уже реализована.

## 7. Subscription logic

**Источник лимитов:** `services/subscription.py` — `PLAN_LIMITS` и `get_user_plan` (в т.ч. наследование TEAM от владельца команды).

Кратко:

|  | FREE | PRO | TEAM |
|--|------|-----|------|
| Проекты | до 3 | без лимита | без лимита |
| Голос (в лимитах) | выкл. | вкл. | вкл. |
| История | 7 д | 90 д | 365 д |
| Шаблоны | standard | все | все |
| AI-редакция, weekly (в лимитах), jira, export | частично нет / да | да | да |
| team_reports, admin_panel | нет | нет | да |

**Нюанс `/weekly`:** в коде проверяется владелец команды; участники команды с планом TEAM **могут не получить** эту команду, хотя в таблице лимитов weekly для TEAM «вкл.» — зафиксировать в продуктовом решении.

**Нюанс дневного job:** рассылка черновика в 17:30 — **только owner**, не всем пользователям.

## 8. Admin / Super Admin logic

- **Super admin в боте:** `SUPER_ADMIN_USERNAMES` (CSV), нормализация `@` и регистра; **по умолчанию** в коде: **`PM_vibe`**.
- **Бот** `@igest_bot` — **не** пользователь-админ; `bot_id` 8603110674 — идентификатор **бота**, не роли в ACL.
- **Веб:** отдельная логика team vs super (см. `web_app` / шаблоны) — super admin = та же схема имён + план TEAM для team-admin зон, детали — в существующем коде.

## 10. Missing pieces for V2

- **Единая настройка `BOT_USERNAME`:** в коде и шаблонах везде строка `igest_bot` — для staging/переименований удобнее централизация (решение — отдельной задачей, не в рамках этого документа как реализация).
- **Синхронизация цен/копирайта** между лендингом V2, `/pro` и фактом Stars (см. прототип vs прод).
- **Theme gating** — в продукте сейчас в основном клиентский/дизайн-контракт; серверного «плана темы» в baseline нет.
- **Report recipients (кому отчёт)** — в прототипе есть, **в бэкенде baseline нет**.
- **Документация env:** `PUBLIC_WEB_APP_URL`, `SUPER_ADMIN_USERNAMES` в `.env.example` отсутствуют.
- **Согласованность** `voice_notes` FREE и фактического поведения бота.
- **«Устаревший» текст** в `/pro` про Stars.

## 11. Safe next implementation step

**Минимальный безопасный шаг (к концепции baseline):** вынести **имя бота** в конфиг/шаблонный контекст **один раз** (переменная вроде `BOT_USERNAME`) и строить все `t.me/...` ссылок от неё — без дублирования логики подписок, оплаты и команд.

*Реализация — только после явного согласования; этот документ фиксирует намерение, не требует правок кода.*

---

## 12. Do-not-rebuild list

- Не дублировать **маршруты** FastAPI для того же сценария (один путь — одна ответственность).
- Не вводить **второй набор** команд бота с тем же смыслом.
- Не плодить **второй** поток оплаты / Stars / precheckout / `successful_payment`.
- Не копировать **логику подписок** (`SubscriptionService`, `PLAN_LIMITS`, активация) — расширять существующую.
- Не менять **семантику** `get_user_plan` / team inheritance без миграции и продукта.
- Не «переизобретать» **super admin** — использовать `SUPER_ADMIN_USERNAMES` + текущий `AdminService`.

## 14. Open decisions

- Выровнять **цены и формулировки** (лендинг V2, `/pro`, Stars 250/700) — single source of truth.
- Нужен ли **автоматический** CTA на оплату (deep link нельзя заменить полноценно без BotFather/доп. сценария) — оставить «открой бота и `/buy`» или invest в UX-обход.
- **Ежедневный job:** только `OWNER_USER_ID` — осознанно ли; нужна ли мульти-рассылка для V2.
- **FREE + голос:** ужесточать gate или обновить маркетинг/лимиты.
- **Срок «weekly»** для участников команды (не владельцев) — продуктовое ТЗ.
- **Темы PRO** — только front+флаг плана на сервере vs чисто клиент (зависит от монетизации).
